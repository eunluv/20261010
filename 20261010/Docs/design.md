# 추리 탐정 사무소 게임 기획서 (초안)

Oct 9, 2026 · @장은정

## 1. 개요

티격태격하는 소꿉친구 탐정 콤비가 매번 새로 생성되는 사건을 조사하고, 증언의 모순을 찔러 범인을 밝혀내는 유머 추리 게임이다. 혼자서도, 친구 2\~4명이 방을 만들어서도 플레이할 수 있다.

| 항목 | 내용 |
| --- | --- |
| 가제 | 미정 (예: 〈소꿉친구 탐정사무소〉) |
| 장르 | 추리 어드벤처 + 증언 반박 + 보드게임식 단서 추론 |
| 분위기 | 애니·서브컬처 감성, 법정 배틀식 유머와 연출 |
| 플랫폼 | PC (Steam) 우선 |
| 인원 | 1인 솔로 / 2\~4인 온라인 협동 (친구끼리 방 만들기) |
| 한 판 길이 | 짧은 사건 15\~20분 / 긴 사건 40분 이상 |
| 비주얼 | 2D 캐릭터 일러스트 + 대사창 (비주얼 노벨 방식) |
| 타깃 | 추리·방탈출·머더 미스터리 보드게임을 좋아하는 서브컬처 팬, 친구와 함께할 가벼운 협동 게임을 찾는 사람 |

**핵심 차별점**

- **매번 다른 사건**: 정답(범인·장소·도구·동기)을 무작위로 정하고 단서를 거꾸로 만들어서, 공략이나 정답 유출이 의미 없다.
- **실행 중 AI 비용 0원**: 사건은 템플릿 조합과 검증 프로그램으로 만든다. AI는 개발 단계의 콘텐츠 제작에만 쓴다.
- **증언 반박의 손맛**: 증언 속 모순에 단서를 들이대는 연출이 게임의 얼굴이다.
- **단서를 나눠 갖는 협동**: 멀티에서는 플레이어마다 다른 단서를 받아, 말로 맞춰야 풀린다.
- **시리즈 구조**: 탐정 사무소를 허브로, 사건 파일(세계관 팩)을 계속 추가할 수 있다.

## 2. 세계관과 캐릭터

모든 사건은 만성 적자에 시달리는 작은 탐정 사무소로 들어온다. 사무소는 사건 선택, 수집, 멀티 로비, 일상 개그가 모이는 허브이고, 시리즈가 바뀌어도 그대로 유지되는 고정 무대다.

### 탐정 사무소 (허브)

- **의뢰 게시판**: 사건 파일을 고르는 곳. 난이도, 모드(짧은/긴), 세계관 팩이 표시된다.
- **사건 기록장**: 해결한 사건, 해금한 캐릭터 프로필과 일러스트, 엔딩 목록.
- **응접실**: 멀티 로비. 친구가 "임시 조수"로 들어오는 연출.
- **잡담 이벤트**: 사건 사이에 콤비의 짧은 만담이 나온다. 밀린 월세, 이상한 의뢰, 서로의 흑역사 같은 소재.

### 주인공 콤비: 티격태격 소꿉친구

어릴 때부터 옆집에 살아 서로의 약점을 다 아는 사이. 평소에는 말다툼만 하지만, 결정적 순간에는 눈빛만으로 통한다. 가끔 묘하게 설레는 순간이 생기지만 둘 다 인정하지 않는다. 이름과 외형은 미정이다.

|  | 미소녀 (가칭: 소장) | 미소년 (가칭: 조수) |
| --- | --- | --- |
| 포지션 | 사무소 소장. 직관형, 현장 돌격대 | 자칭 조수, 실질적 두뇌. 논리형 |
| 성격 | 밝고 고집 셈, 감이 좋다 | 냉정한 척, 잔소리가 많다 |
| 약점 | 덜렁댐, 돈 계산 못 함, 단서를 먹어버림 | 귀신·벌레에 약함, 칭찬에 약함 |
| 게임 기능 | **조사 담당**: 현장 조사, 단서 수집, 용의자 수다로 정보 캐기 | **추리 담당**: 단서 정리·조합, 증언 반박 |
| 만담 역할 | 보케 (엉뚱한 소리) | 츳코미 (지적하는 쪽) |

대사 톤 예시 (초안):

- 소장: "범인은 저 사람이야! …근거? 그건 이제부터 네가 찾아."
- 조수: "매번 결론부터 내지 말라고 했지. 그리고 그 증거품, 왜 반쯤 먹었어?"

### 용의자 아키타입

용의자는 세계관 팩마다 새로 만들되, 아래 틀을 재사용한다. 각자 **말버릇 1개 + 집착 1개 + 거짓말 성향**을 가진다.

| 아키타입 | 개그 포인트 | 거짓말 성향 |
| --- | --- | --- |
| 허세 부자 | 모든 걸 돈으로 해결하려 함 | 체면 때문에 사소한 거짓말 |
| 소심한 목격자 | 말끝마다 사과함 | 거짓말은 못 하지만 중요한 걸 빼먹음 |
| 중2병 | 사건을 운명의 시련이라 부름 | 과장이 심해 진실과 망상이 섞임 |
| 완벽주의 집사·메이드 | 사건 중에도 청소함 | 주인을 감싸려고 거짓말 |
| 수상한 라이벌 탐정 | 콤비보다 먼저 결론을 냄 | 일부러 틀린 추리를 흘림 |
| 무기력한 관계자 | "귀찮아"가 입버릇 | 거짓말은 안 하지만 대답이 짧음 |

거짓말 성향은 단순한 설정이 아니라 사건 생성 규칙에도 쓰인다 (6장).

## 3. 게임 모드

모드는 별도 게임이 아니라 같은 엔진에서 **사건 생성 설정값만 바꾼 것**이다. 길이(짧은/긴)와 인원(솔로/협동)을 자유롭게 조합한다.

|  | 짧은 사건 (15\~20분) | 긴 사건 (40분+) |
| --- | --- | --- |
| 사건 크기 | 용의자 4\~5명, 장소 4곳, 도구 4개 | 용의자 7\~8명, 장소 6\~8곳, 도구 6개 |
| 풀어야 할 것 | 범인 + 장소 + 도구 | 범인 + 동기 + 수법 + 공범 여부 |
| 조사 행동 수 | 6\~8회 | 단계별 6회 × 3단계 |
| 증언 반박 | 1\~2회 | 4\~6회 (최종 반박 포함) |
| 반전 이벤트 | 없음 | 2\~3회 (새 장소 개방, 거짓 증언 발각 등) |
| 단서 수 | 8\~12개 | 25개 안팎 |
| 용도 | 가볍게 여러 판, 일일 사건 | 몰입형 스토리, 주말에 친구들과 |

**솔로**: 조사 담당과 추리 담당을 한 명이 오가며 조작한다. 모든 단서를 혼자 받는다.

**협동 (2\~4인)**: 같은 사건을 플레이어끼리 나눠 푼다. 단서는 플레이어마다 다르게 분배된다 (7장).

**추가 아이디어 (후순위)**: 날짜별 시드로 모든 플레이어가 같은 사건을 푸는 "오늘의 사건"과 기록 랭킹.

조사로 단서를 모으고, 증언 반박으로 새 정보를 여는 과정을 반복하다가 지목으로 사건을 끝낸다. 틀린 반박은 신뢰도를 깎고, 신뢰도가 0이 되면 의뢰 실패로 결말에 간다. 결말의 복기와 보상이 다음 의뢰로 이어지는 동기가 된다.

## 5. 게임 시스템

게임은 조사 → 정리 → 반박 → 지목의 네 시스템으로 돌아가고, 신뢰도가 전체 긴장감을 잡는다.

### 5-1. 조사

- 사건 현장 지도에서 장소를 골라 조사한다. 조사 1회 = 행동력 1 소모.
- 행동 종류: **현장 조사**(물증), **탐문**(용의자 증언·알리바이), **잡담**(용의자의 사적인 정보, 호감 이벤트), **재조사**(이미 본 장소에서 숨은 단서, 행동력 2).
- 행동력이 제한되어 있어서 "어디부터 볼까"가 핵심 선택이 된다. 모든 단서를 다 모을 수는 없지만, 생성기는 **행동력 안에서 정답에 도달할 수 있는 경로가 반드시 있음**을 보장한다.

### 5-2. 단서와 수첩

- 단서는 카드 형태로 수첩에 쌓인다. 종류: 물증, 증언, 알리바이, 관계, 시간 기록.
- 수첩에는 **추리 보드**가 있다. 용의자 × 장소 × 도구 표에 직접 O/X를 표시하는 보드게임식 메모장. 클루의 체크 시트를 디지털로 옮긴 것.
- 두 단서를 겹쳐 새 사실을 얻는 **단서 조합**이 있다 (예: "찢어진 단추" + "연극부 의상 목록" → "범인은 연극부 의상을 입었다").

### 5-3. 증언 반박 (핵심 시스템)

1. 용의자가 3\~5줄짜리 증언을 한다.
2. 플레이어는 줄마다 **추궁**(더 캐묻기, 추가 증언이 나옴) 또는 **반박**(단서 제시)을 할 수 있다.
3. 모순되는 줄에 맞는 단서를 제시하면 증언이 무너지고, 새 정보나 새 증언이 열린다.
4. 틀리면 신뢰도가 깎이고 캐릭터별 핀잔 대사가 나온다.

반박 연출: 화면 정지 → 컷인 → 큰 글씨의 외침 → 효과음. 외침 문구는 자체 제작한다 (예: "잠깐만!", "그 말, 이상해!"). 기존 작품의 대사·연출 문구는 쓰지 않는다.

### 5-4. 신뢰도

- 의뢰인이 사무소를 믿는 정도. 사건 시작 시 5칸.
- 반박 실패, 잘못된 지목 시 감소. 0이 되면 의뢰 실패 (배드엔딩).
- 협동에서는 팀 전체가 공유한다. 누가 틀렸는지 다 보이기 때문에 "누가 깎았어!" 같은 웃음이 생긴다.

### 5-5. 지목

- 행동력을 다 쓰거나 원할 때 최종 추리로 들어간다.
- 짧은 사건: 범인, 장소, 도구를 하나씩 선택. 긴 사건: 여기에 동기, 수법, 공범 여부까지 답하고, 범인의 마지막 발악 증언을 반박해야 한다.
- 협동에서는 각자 답을 고른 뒤 **동시 공개 → 의견이 다르면 토론 → 최종 투표**.

### 5-6. 결말과 복기

- 진상 공개 컷신: 범인의 고백, 사건 재현.
- **복기 화면**: 어떤 단서가 결정적이었는지, 놓친 단서는 어디 있었는지, 최단 해결 경로는 무엇이었는지를 보여준다. 추리 게임의 재미 절반은 여기서 나온다.
- 평가: 사용 행동력, 남은 신뢰도, 걸린 시간으로 등급(S\~C). 등급에 따라 사무소 보수와 수집 요소가 해금된다.

## 6. 사건 생성 로직

원칙은 **정답 먼저, 단서는 나중에**다. 진실을 먼저 정하고, 그 진실과 모순되지 않는 단서를 하나씩 더하다가 정답이 하나로 좁혀지는 순간 멈춘다. 모든 과정은 시드 값 하나로 재현된다.

### 6-1. 생성 단계

1. **시드 결정**: 무작위 또는 날짜 기반 시드. 같은 시드 = 같은 사건 (버그 재현, 일일 사건, 멀티 동기화에 사용).
2. **무대 선택**: 세계관 팩에서 사건 템플릿 1개 선택 (예: "축제 중 분실 사건").
3. **배역 배정**: 용의자 N명, 장소 N곳, 도구 N개를 뽑는다.
4. **진실 생성**: 범인, 장소, 도구, 시간대를 정하고, 긴 사건은 동기·수법·공범까지 정한다.
5. **타임라인 생성**: 사건 전후 시간대별로 모든 용의자가 어디서 무엇을 했는지 정한다. 이것이 모든 단서와 증언의 원천이다.
6. **단서 후보 생성**: 타임라인에서 참인 사실을 뽑아 단서 템플릿에 끼운다.
7. **단서 선택 + 검증**: 후보 중 하나를 고르고, 검증기로 남은 정답 후보 수를 계산한다. 1개가 될 때까지 반복한다.
8. **증언 생성**: 각 용의자의 증언을 만들고, 거짓말 성향에 따라 일부 줄을 거짓으로 바꾼다.
9. **배치**: 단서를 장소·행동에 배치하고, 행동력 안에 해결 경로가 있는지 확인한다.
10. **실패 시 재시도**: 조건을 못 맞추면 시드를 바꿔 다시 만든다. 사건 하나 생성에 1초 이내가 목표.

### 6-2. 단서 템플릿

단서는 문장 템플릿 + 논리 조건으로 이루어진다. 문장은 세계관 팩에서, 논리는 엔진에서 처리한다.

| 유형 | 논리 조건 | 문장 예시 |
| --- | --- | --- |
| 직접 배제 | X는 범인이 아니다 | "{X}는 그 시간 내내 무대 위에 있었다" |
| 장소 배제 | 장소 ≠ L | "{L}은 오후 내내 잠겨 있었다" |
| 도구 배제 | 도구 ≠ T | "{T}에는 먼지가 그대로 쌓여 있다" |
| 연결 | 범인이 쓴 도구는 장소 L에 있던 것 | "없어진 물건은 모두 {L}의 비품이었다" |
| 조건부 | X가 범인이면 장소는 L | "{X}가 {L}에 가는 걸 누가 봤대" |
| 속성 | 범인은 속성 P를 가진다 | "범인은 왼손잡이로 보인다" |
| 시간 | 시각 t에 X는 장소 L | "3시에 {X}는 매점에 있었다" |

### 6-3. 검증기 (솔버)

- 가능한 모든 정답 조합(용의자 × 장소 × 도구, 짧은 사건 기준 4×4×4 = 64개)을 나열하고, 지금까지의 단서와 모순되는 조합을 지운다.
- 남은 조합이 1개면 "풀 수 있는 사건". 0개면 단서끼리 모순이므로 버그.
- 긴 사건은 조합이 수천 개로 늘어나지만, 이 정도는 단순 나열로도 충분히 빠르다. 느려지면 제약 전파 방식으로 바꾼다.
- 같은 솔버로 **힌트 기능**도 만든다: "지금 가진 단서로 지울 수 있는 후보가 아직 남아 있어요."

### 6-4. 증언 모순 생성

- 증언의 각 줄은 타임라인의 사실을 말한다.
- 거짓 줄은 "사실을 살짝 바꾼 문장"으로 만든다 (장소, 시간, 물건 중 하나를 바꿈).
- 거짓 줄마다 **그것을 반박하는 단서가 최소 1개 존재하고, 플레이어가 얻을 수 있는 위치에 있도록** 배치한다.
- 거짓말 성향 활용: 소심한 목격자는 거짓 대신 "빠진 정보"(추궁하면 나옴), 중2병은 과장(사실은 맞지만 표현이 틀림), 집사는 주인 감싸기.

### 6-5. 난이도 조절 변수

| 변수 | 쉬움 | 어려움 |
| --- | --- | --- |
| 단서 유형 비율 | 직접 배제 위주 | 조건부·속성·시간 위주 |
| 가짜 단서 (참이지만 무관한 정보) | 0\~1개 | 3\~4개 |
| 행동력 여유 | 최단 경로 + 4 | 최단 경로 + 1 |
| 거짓 증언 수 | 1개 | 3개 이상 |
| 힌트 | 사용 가능 | 사용 시 등급 감점 |

### 6-6. 반복감 줄이기

- 같은 단서 유형에 문장 변형을 최소 3\~5개씩 준비한다.
- 사건 템플릿마다 "고정 개그 이벤트"를 1\~2개 넣는다 (사건과 무관한 소동).
- 최근 N판에 나온 용의자 조합, 사건 템플릿은 가중치를 낮춘다.

## 7. 멀티플레이 설계

협동의 재미는 **각자 다른 단서를 들고 말로 맞추는 것**에서 나온다. 기술적으로는 방장이 사건을 만들고 나머지는 결과만 받는 단순한 구조로 간다.

### 7-1. 역할

| 인원 | 역할 구성 |
| --- | --- |
| 2인 | 소장(조사 담당) + 조수(추리 담당) |
| 3인 | + 정보통: 탐문과 잡담 행동이 강화됨 |
| 4인 | + 감식반: 재조사 비용이 싸고 단서 조합 성공률이 높음 |

역할은 선호일 뿐 행동을 막지는 않는다. 누구나 조사와 반박을 할 수 있다.

### 7-2. 단서 분배

- 같은 장소를 조사해도 **조사한 사람만 단서 전문을 본다.** 다른 사람에게는 "OO가 무언가를 발견했다"만 표시된다.
- 단서를 공유하려면 직접 말하거나, 행동력 1을 써서 **단서 공유**를 해야 한다. 말로 설명하다 생기는 오해와 웃음이 협동의 재미다.
- 증언 반박은 단서를 가진 사람만 할 수 있다. 그래서 "그 단서 누가 갖고 있어?"가 자연스러운 대화가 된다.
- 행동력은 개인별로 따로, 신뢰도는 팀 공유.

### 7-3. 진행 방식

- **동시 진행**: 조사 단계는 각자 동시에 움직인다 (턴 대기 없음).
- **합류 단계**: 증언 반박과 지목은 모두 한 화면에 모여서 진행한다. 반박은 누구든 먼저 누른 사람이 한다.
- 음성 채팅은 디스코드 등 외부 도구를 쓴다고 가정하고, 게임 안에는 텍스트 채팅과 핑("여기 봐!")만 둔다.

### 7-4. 기술 구조

- **방장 권한 구조**: 방장이 사건을 생성하고 모든 판정(단서 지급, 반박 성공 여부)을 한다. 참가자는 입력만 보낸다. 부정행위를 막고 동기화를 단순하게 만든다.
- **시드 공유**: 사건 전체가 아니라 시드만 보내면 모든 클라이언트가 같은 사건을 재현할 수 있다. 단, 정답 정보는 방장만 계산해서 메모리 해킹으로 답을 보는 걸 어렵게 한다.
- **Steam 연동**: Steam 친구 초대, 로비, P2P 연결(Steam Networking)을 사용한다. 전용 서버가 필요 없어 서버 비용이 거의 들지 않는다.
- **재접속**: 연결이 끊긴 플레이어가 돌아오면 방장이 현재 상태를 다시 보낸다.
- **방장 이탈**: 초기 버전은 판 종료로 처리하고, 이후 방장 이전 기능을 검토한다.

## 8. 유머와 연출, 수집 요소

유머는 템플릿으로 재사용할 수 있는 자리에 집중적으로 넣는다. 한 번 써두면 모든 사건에서 계속 터지는 자산이 된다.

### 8-1. 유머를 넣는 자리

- **오답 핀잔**: 틀린 단서를 제시했을 때 콤비와 용의자의 반응 대사. 단서 유형 × 캐릭터별로 준비한다.
- **콤비 만담**: 조사 중 랜덤으로 나오는 짧은 대화 (소장의 엉뚱한 추리 → 조수의 지적).
- **용의자 말버릇**: 증언과 잡담에 계속 섞여 나온다.
- **엉뚱한 단서**: 사건과 무관하지만 웃긴 물건 ("누군가의 연애편지 초안"). 가짜 단서 역할도 한다.
- **온도 차**: 가벼운 소재로 시작해서, 긴 사건 후반에 진지한 동기가 밝혀지는 반전.

### 8-2. 연출

- 캐릭터 일러스트 + 대사창. 표정 차분, 웃음, 놀람, 당황, 화남 정도부터 시작.
- 반박 성공 시 컷인, 화면 흔들림, 효과음, 배경음 전환.
- 범인 확정 시 범인의 "무너지는 연출"(캐릭터마다 다른 리액션). 팬들이 가장 기억하는 장면이 된다.

### 8-3. 수집과 반복 동기

- **캐릭터 프로필**: 용의자와 처음 만나면 해금, 잡담하면 숨은 정보 추가.
- **사건 기록장**: 해결한 사건과 등급 기록.
- **일러스트 갤러리**: 등급 보상, 특정 조건 달성 시 해금.
- **콤비 에피소드**: 사건 N개 해결마다 두 주인공의 과거 이야기 한 편이 열린다. 소꿉친구 관계의 설렘 포인트를 여기서 풀어서, 시리즈 내내 이어지는 메인 스토리 역할을 한다.
- **엔딩 수집**: 잘못된 지목 시 나오는 배드엔딩도 개그 엔딩으로 만들어 수집하게 한다.

## 9. 시리즈 확장 구조

엔진은 한 번 만들고, 세계관 팩(사건 파일)만 갈아 끼워 시리즈를 늘린다. 팩마다 고유 규칙 하나를 더해서 매번 다른 게임처럼 느끼게 한다.

**엔진(공통)**: 사건 생성기, 검증기, 조사·반박·지목 시스템, 멀티플레이, 대사창 UI, 사무소 허브.

**세계관 팩(교체)**: 사건 템플릿, 용의자, 장소, 도구, 단서 문장, 일러스트, BGM, 고유 규칙 설정. 모두 데이터 파일로 분리한다.

| 팩 (예시) | 사건 분위기 | 고유 규칙 모듈 |
| --- | --- | --- |
| 1탄: 학원 축제 | 가벼운 학원 소동 | 호감도: 친해진 용의자만 속마음 단서를 말함 |
| 2탄: 괴담 마을 | 시골 마을의 저주 소문 | 정신력: 낮아지면 가짜 단서가 섞여 보임 |
| 3탄: 호화 여객선 | 밀실, 부자들의 암투 | 시간 제한: 배가 항구에 닿기 전에 해결 |
| 4탄: 마법 학원 | 판타지 | 마법 흔적: 특정 행동으로만 보이는 단서 |

**출시 전략**: 본편(엔진 + 1탄)을 먼저 내고, 반응이 좋으면 2탄부터 DLC로 판다. 팩이 충분히 쌓이면 독립 타이틀이나 확장판으로 묶는다.

**현지화 대비**: 모든 문장은 처음부터 문자열 테이블로 분리한다. 한국어 → 일본어 → 영어 순서를 추천한다 (서브컬처 추리 장르는 일본 시장이 크다).

**장기 확장 (후순위)**: 팩 제작 도구 공개, Steam 워크샵으로 유저 제작 사건 팩 지원.

## 10. 기술 구현

엔진은 **Unity (확정)**를 추천한다. 어느 쪽이든 사건 생성기와 검증기는 엔진과 분리된 순수 로직으로 만들어, 화면 없이 테스트할 수 있게 한다.

### 10-1. 엔진 비교

| 엔진 | 장점 | 단점 | 용도 |
| --- | --- | --- | --- |
| Godot | 무료·오픈소스, 2D에 강하고 가벼움, Steam 연동 플러그인(GodotSteam) 있음 | Unity보다 자료와 에셋이 적음 | 본 개발 추천 |
| Unity | 자료·강좌·에셋 풍부, Steam 연동 라이브러리 성숙 | 무겁고, 과거 요금 정책 변동 이력 | 본 개발 추천 |
| Ren'Py | 비주얼 노벨 특화, 대사·연출을 빠르게 만듦 | 멀티플레이와 복잡한 시스템에 약함 | 초기 프로토타입만 |

### 10-2. 아키텍처

&#91;embedded content: 엔진 구조 · 팩 데이터 → 생성·검증 → 상태 → UI·네트워크\]

세계관 팩은 데이터 파일로만 존재하고, 엔진 코어가 그것을 읽어 사건을 만든다. 게임 상태는 방장만 바꿀 수 있고, UI와 네트워크는 그 상태를 보여주거나 전송할 뿐이다.

### 10-3. 데이터 구조 예시

단서 템플릿 (팩 데이터):

```json
{
  "id": "alibi_stage",
  "logic": { "type": "exclude_suspect", "requires": "suspect_at_place_during_crime" },
  "text": [
    "{suspect}는 그 시간 내내 {place}에 있었다.",
    "{place}의 CCTV에 {suspect}가 계속 찍혀 있다."
  ],
  "source": ["investigate", "interview"]
}
```

생성된 사건의 진실 (방장만 보유):

```json
{
  "seed": 20261009,
  "template": "festival_missing_item",
  "truth": { "culprit": "drama_captain", "place": "storage", "tool": "costume_rack", "time": "15:00" },
  "timeline": [ { "time": "15:00", "who": "drama_captain", "where": "storage" } ],
  "clues": ["alibi_stage:butler", "locked:music_room", "link:tool_from_storage"]
}
```

**구현 원칙**

- 같은 시드는 항상 같은 사건을 만든다 (엔진 내장 난수 대신 시드 고정 난수기 사용).
- 모든 문장은 문자열 테이블에, 코드에는 ID만 둔다 (번역 대비).
- 생성기에는 자동 테스트를 붙인다: 시드 1만 개를 돌려 풀 수 없는 사건이 0개인지 확인.
- 코딩은 Claude 같은 AI 코딩 도구의 도움을 받되, 생성·검증 로직은 직접 이해하고 있어야 디버깅이 가능하다.
- 힌스필드 같은 생성 도구는 콘셉트 시안과 트레일러 제작에 활용하고, 게임 실행 중에는 쓰지 않는다.

## 11. 개발 로드맵과 프로토타입 범위

가장 먼저 증명할 것은 "랜덤 사건이 매번 풀 수 있고, 재밌다"는 것 하나다. 그래서 그래픽과 멀티플레이는 뒤로 미루고 텍스트만으로 사건 생성기부터 만든다. 기간은 혼자 작업 기준의 대략적인 추정이며, 작업 시간에 따라 크게 달라진다.

1. **0단계 – 종이 프로토타입 (1\~2주)**
   - 단서 카드를 종이로 만들어 친구와 직접 플레이. 단서 유형, 행동력 수, 반박 규칙이 재밌는지 확인한다.
2. **1단계 – 텍스트 생성기 (3\~6주)**
   - 사건 생성기 + 검증기 + 텍스트 출력만. 화면 없이 콘솔에서 사건 100개를 뽑아 모두 풀 수 있는지, 난이도가 고른지 검사한다.
   - **통과 기준**: 생성 사건 100% 해결 가능, 직접 풀어본 20판 중 대부분이 "한 판 더"하고 싶음.
3. **2단계 – 솔로 수직 슬라이스 (2\~3개월)**
   - 사무소 화면, 조사, 수첩, 증언 반박, 지목, 복기까지 한 바퀴. 임시 그림으로 시작.
   - 콘텐츠: 주인공 2명(표정 각 3\~5종), 용의자 6명(표정 각 2\~3종), 사건 템플릿 3\~5개, 짧은 사건만.
   - **통과 기준**: 외부 테스터 5\~10명이 설명 없이 끝까지 플레이.
4. **3단계 – 협동 멀티 (1\~2개월)**
   - Steam 로비, 단서 분배, 합류 단계, 동시 공개 투표.
5. **4단계 – Steam 페이지 + 데모 (1개월)**
   - 정식 일러스트, 트레일러, 스토어 페이지 공개, 위시리스트 모으기, Steam 넥스트 페스트 참가 검토.
6. **5단계 – 정식 출시 준비**
   - 긴 사건 모드, 반전 이벤트, 수집 요소, 콤비 에피소드, 일본어 번역.

협업자 2\~3명이 합류한다면 일러스트레이터, 시나리오(단서 문장·대사), 사운드 순으로 우선순위를 둔다.

## 12. 리스크와 미정 사항

가장 큰 리스크는 "랜덤 단서가 기계적으로 느껴지는 것"이다. 이건 1단계 텍스트 생성기에서 가장 먼저 확인한다.

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| 템플릿 단서가 반복적·기계적으로 느껴짐 | 재미의 핵심 붕괴 | 문장 변형 확대, 고정 개그 이벤트, 손으로 쓴 사건 템플릿 혼합 |
| 랜덤 증언 반박이 억지스러움 | 핵심 시스템 약화 | 거짓 줄 생성 규칙을 좁게 시작하고, 테스트로 다듬기 |
| 범위가 커져 완성 전에 지침 | 미출시 | 로드맵 단계별 통과 기준 지키기, 긴 모드는 후순위 |
| 멀티 동기화 버그 | 협동 경험 망가짐 | 방장 권한 구조, 솔로 먼저 완성 후 얹기 |
| 일러스트 비용·작업량 | 일정 지연 | 캐릭터 수·표정 수 제한, 일러스트레이터 협업 검토 |
| AI 생성 그림 사용 | 팬층 반감, Steam 고지 의무 | AI는 기획·시안용으로만, 최종 그림은 직접·외주 권장. 출시 전 Steam 규정 재확인 |
